# proxy-forge

Turns a Magic: The Gathering deck list into printable proxy cards with generated art, in a small local web page. For personal playtesting only: not for sale, not for distribution.

All of the models' work is the **studio's** (`D:\ebook-av-service`, port 7860), through its `/v1/ai` API (`ebook-av-service/docs/AI-API.md`; the client is `proxy_forge/studio.py`): its language model (`qwen2.5:14b`) writes the art prompts, its vision model (`qwen3-vl:8b`) describes reference photos, its ComfyUI draws the art (Anima-Turbo, with LoRAs from `G:\studio-models\anima-loras`) and its trainer makes the person LoRAs. Proxy-forge keeps what is its own: cards, templates, prompts, style profiles, people and photos. The shared package **`../studio-kit`** still supplies the sign-in check (`web_auth`, `clerk_auth`).

## Run

Start the studio first (`D:\studio-home\start-studio.ps1`, or its scheduled task `EbookAV Studio`: studio + ComfyUI + Ollama), then:

```powershell
D:\proxy-forge\start-proxy-forge.ps1      # http://127.0.0.1:7870
```

Tests: `.venv\Scripts\python.exe -m pytest` (no GPU, no network).

Data (Scryfall index, profiles and photos, art cache, decks) is under `G:\proxy-forge-data` (`PROXY_FORGE_DATA` to move it). Nothing goes on C:.

## How it works

1. **Style**: verbal direction, an optional LoRA, and *people*. A person's photos are described by the local vision model as tags plus a sentence (edit it if it is off); those words go into every card they are assigned to. Anima has no image-prompt adapter, so the written description alone is approximate (hair, glasses, build), not a face match. For a real likeness, train a **per-person LoRA** (below).
2. **Template**: `proxy_forge/templates/*.json` (geometry, fonts, colours, a drawing `style`). Changing the template re-draws the cards instantly, without drawing new art.
3. **Deck**: paste a list (`4 Lightning Bolt`, `4x Counterspell (MH2) 267`, `Sideboard`, `SB: 2 Negate`). Cards come from Scryfall's bulk `oracle_cards` file (downloaded once, indexed in SQLite); a misspelt name goes to Scryfall's fuzzy search once. Double-faced cards get one card per face; split and adventure cards are one card.
4. **Make it**: prompts for every card first (the studio's language model), then the art is drawn (the studio frees the language model if the card is short of memory) (about 5 s a card after the first). Art is cached by what was asked for, so a re-run draws only what changed. Click a card to edit its prompt or seed, choose who is in it, and redraw just that card.
5. **Export**: PDF sheets (3x3, US Letter or A4, cut marks) or a ZIP of PNGs, 750x1050 px = 2.5 x 3.5 in at 300 dpi. Every card carries a small "PROXY · art generated by AI · not for sale" line.

## Person LoRAs (real likeness)

On a person's card in the Style panel, **Train LoRA from photos** (6 photos minimum, 15-30 varied ones is best: different days, angles, lighting, expressions). Proxy-forge sends the photos to the studio, which trains with its own trainer (`G:\anima_lora`, T-LoRA on Anima, settings `ebook-av-service/lora/series-template.toml`) and deletes the photos again when the run ends:

1. Each photo is captioned by the studio's local vision model (`safe, 1boy, <trigger>, photo, realistic, <expression, pose, clothes, background>`). The person is tied to a made-up trigger word, never a real name. "photo, realistic" is deliberate: the model learns the photographic look as a property of those words, so leaving them out keeps the drawings illustrations.
2. The trainer runs about 1000 steps by default (the slider in the Style panel; about 20-25 minutes on the 5090; the studio's GPU is busy and its other jobs wait) and saves four checkpoints. The studio moves the trainer's working folders aside for the run and puts them back afterwards, so its series LoRA work is untouched.
3. **Compare checkpoints** draws the same test picture with each one so you can pick by eye (the studio found a middle checkpoint can beat the last: overfit). Strength 0.8 by default; lower it if the photographic look leaks, raise it if the face is weak.
4. Cards this person is assigned to are drawn with their LoRA stacked on the style LoRA, and the trigger word is added to the prompt at draw time, so no prompts need rewriting. Checkpoints and a card are written by the studio to `G:\studio-models\anima-loras` (`pf_<person>-...`), where ComfyUI finds them; the studio's iOS list of LoRAs leaves them out.

Photos of real people in an anime model: the face comes through, the rendering style should not; if it does, lower the strength or pick an earlier checkpoint.

## Fonts and symbols

- **Symbols:** the [Mana](https://github.com/andrewgioia/mana) icon font (SIL OFL), `fonts/mana.ttf` + `fonts/mana.css` (v1.18.0, from the `mana-font` npm package), drawn the way Magic prints them: coloured disc, black icon, drop shadow on the cost; hybrid, phyrexian, `{2/W}`, snow, tap and untap included. `scripts/extract_mana_glyphs.py` rebuilds `fonts/mana-glyphs.json` from the CSS.
- **Text:** Magic uses Beleren (names, type line) and MPlantin (rules text). Those are Wizards' fonts: `fonts/beleren.ttf` and `fonts/mplantin.ttf` (copies hosted in the mana-font package, fetched for personal use; do not redistribute) are used first. MPlantin has no italic here, so reminder text uses Calisto MT Italic (installed with Windows/Office), which is also the fallback for everything if those files are absent. A `mplantin-italic.ttf` in `fonts/` would be picked up; cards redraw automatically when the fonts, templates or drawing code change.
- `scripts/symbols_sheet.py` and `scripts/card_preview.py` render contact sheets for checking the look.

## Adding a template

Copy `proxy_forge/templates/classic.json` (or put one in `G:\proxy-forge-data\templates`), move the boxes (coordinates in the 750x1050 card), change colours or fonts. A new *look* (not just a layout) is a new function in `render.py`'s `STYLES`.

## The tunnel

Its own Cloudflare named tunnel `proxy-forge` (id `efc2531d-…`) -> `https://proxies.hunterthemilkman.com` -> `localhost:7870`, started by `start-proxy-forge.ps1` with `cloudflared/proxy-forge.yml` (the credentials JSON beside it is a secret and git-ignored). The studio's tunnel and the owner's other tunnels are untouched.

The one step that needs the owner: point the hostname at the tunnel (a DNS record in the owner's Cloudflare account):

```powershell
& "C:\Program Files (x86)\cloudflared\cloudflared.exe" tunnel --config D:\proxy-forge\cloudflared\proxy-forge.yml route dns proxy-forge proxies.hunterthemilkman.com
```

Sign-in (`studio_kit/web_auth.py`): at home (localhost) nothing is asked. A request that comes through the tunnel must carry a Clerk session token of an allowed user (same Clerk instance and same `D:\studio-home\clerk-users.txt` as the studio), or the script secret in `tunnel-token.txt` (optional). With neither configured, the app refuses everything from outside. The page signs the visitor in with Clerk and then fetches pictures and downloads with the token.
